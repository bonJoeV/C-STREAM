# Session 14: Ozobot Challenge

## Lesson at a glance

Grades 3-4; Bi-Weekly B; Computing; **one 40-minute meeting**.
**Objective:** draw/test a verified command, compare expected/actual output and
retest one documented route correction. **Why:** optical programming depends
on real sensing, not guessed colors. Catholic/CST-C1 accurate claim limits;
CST-T1 sensor/operation; CST-T2 sequence/debug; CST-M1 route length/comparison.
Official alignment **VERIFICATION REQUIRED**. Technology **Required** for
robotics; tablet/OzoBlockly not required. Developing, novice rehearsal supplied.
Prep 20 after charging/chart secured; loan/model verification extra; cleanup 5.

## Before class and exact supplies

Use unchanged [Session 2](Session02_Ozobot_Coding.md) chart/model gates.
Two robots/chargers/trays and one official matching chart. Record model/manual/
calibration procedure, one documented low-speed command's exact entry/order/
widths; pretest twice, no guessed color table. If failed, paper pathway or
line-following observation only, **command operation not observed**.
Teams <=3 (4/5/7/9): two route sheets/ruler/four chart-compatible markers.
Each pupil evidence paper/pencil. Teacher board/timer/demo from issued station.
Use unbranched roughly 30 cm route, stopped retrieval, two-minute slots:
five rounds across two trays maximum.

## Vocabulary/background/SAFETY

Sensor = detects input; command = documented pattern; calibration = adjust
sensing; debug = test one correction. **Misconception:** any stripe is code.
**If asked "Does it understand our goal?"** Hardware/program respond to inputs,
not human intentions. Tape/line following alone is not command programming.
Dry trays away from edges, no races/liquids/ink on robot; teacher charges/
calibrates. Stop/report failed sensor or unsafe setup. Indoor primary.

## Meeting 1: exactly 40 minutes

1. **0-4:** "What evidence makes a command trustworthy?"
2. **4-10:** Demonstrate verified chart/input/output and safe start/stop.
3. **10-22:** Teams draw/measure route; five two-minute paired-station rounds.
   Each pupil constructs part, starts/tests and records actual output; peers
   trace while waiting. No "expert" self-rating evidence.
4. **22-32:** Same rounds retest one width/spacing/entry correction supported by
   matching guide. Record pass/not yet and same command/route length.
5. **32-35:** Each gives expected/actual, measured route, correction and source
   limit; roster marks real operation separately.
6. **35-40:** Adult off/count/store, pupils cap markers/file dated routes.

## Success/access/troubleshooting

Meets: verified input/output, individual construction/test and debug evidence.
Grade 3/support: traced route/official pattern/read-aloud/scribing.
Grade 4/challenge: explain pattern-position/entry tradeoff, no guessed branches.
Failure: inspect chart/entry/width/calibration one at a time. One robot can't
cover full turns in these windows: log completed turns, schedule missing.
No robot/chart: same times named paper command/token trace/correction, CT only,
**sensor/command programming not observed**. Early finish: equal repeat, not racing.

**Family:** We checked documented optical commands. Ask, "Which source supported
your correction?" Say paper debugging if hardware path was not released.

## Teacher artifact pack (lesson-specific release checklist)

- **Student material (print/no-print):** Print one **Verified Optical Command Test** sheet per pupil with `Robot/model ID ____`, `Official model/manual/chart title or code ____`, `Exact documented command pattern ____`, `Entry direction arrow [drawing box]`, `Measured unbranched route ____ cm`, `Expected documented output ____`, `Run 1 actual output/pass-not yet ____`, `My construction/start/test role ____`, `One supported variable changed: width / spacing / entry / calibration (circle one)`, `Why that change matches the guide ____`, `Retest actual output/pass-not yet ____`, and `Claim limit ____`. Add a 30 cm route drawing box to the team route sheet. In no-print mode, pupils copy the headings while the teacher provides a traced route and handwritten verified pattern; color-name abbreviations and the chart's order must remain exact.
- **Evidence and answer guidance:** Evidence must identify the actual robot model and matching official source, reproduce the teacher-pretested low-speed command's exact entry/order/width requirements, show a roughly 30 cm unbranched measured route, distinguish expected from observed behavior, document the pupil's real operation, and retest one variable while holding command and route length constant. Accept `not yet--continued line following instead of the charted response` as valid actual evidence. A successful claim requires an observed matching output; paper tracing alone earns computational-design/debug evidence but is labeled `sensor/command programming not observed`.
- **Worked example and finished example:** After preflight, display the actual issued robot model, matching chart title/revision, exact documented command, entry direction, measured route, expected output, first observed result, one guide-supported change, and retest result. Copy those values from the verified materials; do not use fill-in blanks or an illustrative color sequence. State the bounded claim for that model and calibration only.
- **Visual example and board setup:** Set up two numbered robot trays away from table edges, each with one pretested route/start orientation; place the single official matching chart where both stations can consult it without removing it. The board should show `MODEL + OFFICIAL SOURCE → EXACT INPUT → EXPECTED OUTPUT → ACTUAL OUTPUT → ONE GUIDE-SUPPORTED CHANGE → RETEST`, a 30 cm metric reference, five two-minute round slots, and role checks `construct / start-test / record`. Post `stopped robot retrieval only`, `no races`, and an explicit entry arrow beside the enlarged verified pattern.
- **Discussion with acceptable response, and misconception:** Ask `What can the optical sensor detect here?` (line/color contrast presented within model requirements); `Why is a stripe not automatically a command?` (order, widths/spacing, entry, calibration, surface, and documented model support matter); `Why cite the chart/model?` (commands differ and a trustworthy claim needs a matching source); `What makes the debug comparison fair?` (same robot, command, route length, and expected output while one named variable changes); `Does the robot know our purpose?` (no--hardware/software respond to inputs); and `Does fastest win?` (no--the objective is verified operation and evidence). Correct claims based on guessed color tables, tape-only line following, racing, or simultaneous changes.
- **Kit contents, kit label, cleanup and reset:** Kit label: **S14 OZOBOT--STATIONS 1-2**. The fixed station case contains exactly 2 numbered robots, 2 chargers, 2 sorting trays, and 1 official chart matching the issued model; the teacher records model/manual/calibration/pretest details on the lid card. Each team packet is labeled **S14 ROUTE--TEAM __** and contains 2 route sheets, 1 metric ruler, and 4 chart-compatible markers; issue one evidence sheet and pencil per pupil. Reset sequence: pupils cap/count four markers, stack both routes and ruler; adult stops and powers off robots, inspects wheels/casing, records charge/fault status, returns each robot and charger to its numbered slot, and quarantines rather than reissues failed hardware.
- **Unfinished work:** Mark the exact achieved level: `SOURCE/PATTERN COPIED`, `ROUTE MEASURED`, `PREDICTION ONLY`, `REAL RUN RECORDED`, or `CORRECTION AWAITS RETEST`. Preserve the route flat with its entry direction and robot/model ID. Schedule only missing individual operation turns; do not convert watching a teammate into operation evidence. If either the matching chart or safe robot is unavailable, use the named paper command/token trace at the same time and stamp `CT ONLY--SENSOR/COMMAND OPERATION NOT OBSERVED`.
- **Annotated exemplar, common error and reteach:** Callouts identify `matching model/source`, `pattern fidelity`, `entry`, `cm length`, `expected`, `actual`, `one variable`, `retest`, and `bounded claim`. A correct-looking route with no source is an unverifiable command; locate the matching chart before testing. A turn/run before reaching the pattern suggests start/entry or route geometry, not proof of bad code. An unchanged output after simultaneous recalibration, redraw, and marker swap cannot identify a cause; restore the known-good route and vary one documented factor. Repeated failure on the teacher's known-good route triggers adult equipment/calibration isolation and **OUT OF SERVICE**, not pupil guesswork.
- **Safety classification:** **Severity: moderate; likelihood: unlikely** with controls, covering battery device damage, a falling robot, or contact with a warm/damaged unit. Adult ratio: **1 adult to no more than 6 pupils at the two active robot trays**; waiting teams remain at paper stations. Robots stay on dry, level trays away from edges; pupils start/observe and retrieve only after motion stops, never race, block wheels, mark the robot, touch charging contacts, or charge/calibrate. Adult stops use for heat, odor, swelling, exposed battery, cracked casing, or sensor fault. **Commercial-product hold:** Used markers. Enter the exact manufacturer/product in [Safety Data Sheet Register](../../../Review/Safety_Data_Sheet_Register.csv). Keep each listed product on **HOLD** until school approval and SDS applicability are resolved; do not infer a brand or claim SDS N/A.
- **Print/accessibility check:** Enlarge the official pattern without altering proportions; pair each color with its written name and a distinct pattern/position cue, use thick high-contrast route lines, large entry arrows, and grayscale-readable field labels. Provide traced routes, ruler stabilization, oral prediction/scribing, low-vision chart enlargement approved against the original, and a partner or teacher start action for motor access while still recording the pupil's decision/test observation. Never make color naming alone the measure of coding understanding.
- **Device compliance:** This lesson requires only the school-owned, model-verified Ozobot hardware and printed matching official chart. Record asset/model IDs and teacher preflight locally; no student account, tablet, OzoBlockly, cloud service, web search, personal device, location data, or image upload is authorized. Optional school photography is not evidence and requires local consent/retention rules. If hardware/model/chart verification is missing, report the technology objective as not observed rather than simulating success. Paper/unplugged work is not executed-device evidence; until the approved device or hardware turn is witnessed, operation remains deferred/not observed.
