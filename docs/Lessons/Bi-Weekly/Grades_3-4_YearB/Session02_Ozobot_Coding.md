## Before class

1. Confirm model and loan; do not assume CSCOE inventory. Obtain its official chart from the kit or [Ozobot color-code resources](https://ozobot.com/create/color-codes/) (also keep the existing family resource **ozobot.com**).
2. **VERIFICATION REQUIRED:** code order, entry direction, line/segment widths and calibration procedure for the actual model. The previous unsourced U-turn/spin/turbo color list has been removed. Do not replace it with guessed colors.
3. Choose **one speed-change command** from that chart, copy its exact colors/label to the board and record `model / chart title / command / teacher observed output`. Test it twice. Choose a slow setting, not a race/turbo challenge. If chart/testing unavailable, **announce line-following observation only; command programming not observed**, or use the paper pathway.
4. Draw one smooth, unbranched black line on white paper, roughly 30 cm long, with rounded bends and clear start/end. Start around 5 mm width, then adjust to the model's instructions. Prepare a second line with the verified code on a straight portion. Follow the model guide for calibration; do not guess power-button timing.
5. Pair pupils, final trio if odd. Two desk testing trays; assign seven one-minute rounds at most for thirteen teams.

## Vocabulary and teacher background

**Sensor:** hardware detecting information. **Input:** sensed line/color. **Output:** movement/light response. **Command:** instruction represented by a verified color pattern. **Calibration:** adjusting sensing for the surface. **Debug:** compare expected and actual, change one thing and retest.

Ozobot does not "think" like a person; onboard programs respond to sensor readings. A line-following demonstration is **not proof that a pupil programmed it**. A pupil-created, tested, compatible color command is additional programming evidence. Branch choices are not guaranteed without verified instructions.

**Misconception:** "Any colorful stripe is code." The model expects particular patterns and spacing.
**If asked:** "Why didn't it obey?" Answer: "Check the model chart, entry direction, colors, spacing and calibration one at a time. An invented command cannot be fixed by trying harder."

## SAFETY

Use only desk trays; prevent falls at table edges. Teacher handles charging and calibration controls; dry paper/clean hands. Keep robots/small parts out of mouths and away from younger children. No racing, stairs, liquids or marker ink on the robot. Cap markers during tests; stop motion before retrieval.

## Numbered sequence: exactly 40 minutes

1. **0-4: Purpose.** Original prayer: "God, help us be truthful and patient with one another." Ask: "What does a sensor detect? Does a robot understand kindness the way a person does?"
2. **4-10: Model input/output.** Teacher shows baseline line-following, then the preverified speed-change command. Point to model chart. "What input changed? What output did we actually see?" If not verified, explicitly teach only observed line following.
3. **10-15: Paper prediction.** Partners trace a line with a token and sequence cards: follow route, read named command, change speed. Use "slow" as a **paper rule**, not a claim about an unverified color combination. Swap reader/executor.
4. **15-27: Draw/test slots.** Teams draw a smooth line and the exact verified code, with correct entry direction from the chart. In one-minute slots across two trays, one child places/starts, another observes output, then swap on a retest. Trio adds chart checker. Teacher logs each child's real operation/command evidence; waiting teams trace and label route.
5. **27-32: Debug one thing.** Teacher chooses a failed line or code. Change line width, segment spacing or calibration **one at a time**, per guide. Retest. "Which change is supported by the result?"
6. **32-35: Individual evidence.** Child names input/output, points to the documentation used, and explains one expected/actual difference. Paper-only children identify a sequence bug; do not claim real color decoding.
7. **35-40: Cleanup.** Teacher switches off/stores robots and counts kits; pupils cap markers, collect paper/tokens/rulers, clear trays and hand in slips.

## Unplugged / indoor alternative

Use the same sequence/time windows. Teacher follows named paper rule cards with a token; partners insert a wrong instruction, find the first mismatch, replace it and retest. No invented color chart. Label **CT sequencing/debugging observed; sensor/robot programming not observed**. All pathways are indoor, independent of winter and internet.

## Success, troubleshooting, support and challenge

**Success:** child predicts a sequence, identifies input/output and documentation, and explains one debug change. Actual robot programming additionally requires that child's verified command construction/test, not simply watching line following.
Score **1** guess; **2** trace with help; **3** independent prediction/debug/evidence distinction; **4** explains a hardware/model limitation.

- **No chart / unexpected response:** stop the color-code claim; use observed line following or paper sequence and report missing programming evidence.
- **Leaves line:** smooth solid width, plain white surface, gentle curves, calibration per model. No guessed "connect Ozobot" tablet requirement.
- **Support / Grade 3:** pre-drawn route and adult marker assistance; child chooses/checks command and predicts.
- **Challenge / Grade 4:** compare two trials, explain why successful sensing differs from successful paper execution; OzoBlockly is a later optional extension with separate setup.
- **25 pupils:** thirteen stationary teams, two trays, seven rounds; no multi-mission race. With one robot, use a teacher demonstration and log who actually tests.

## Family snippet

We checked a robot's documentation, predicted a route and debugged one input. Paper tracing shows computational thinking, not actual robot sensing. Our Catholic connection was honest evidence and respectful shared work. **Ask:** "What did you verify before calling it a command?" **Optional at home:** create and test three named paper rules with a token; **ozobot.com** has optional resources. No robot purchase or homework.
