# Session 04: Robot Friends

## Lesson at a glance
| Field | Teacher information |
|---|---|
| Grade / unit / title | Grades 1-2 / Coding / Robot Friends |
| Time / domains | One 30-minute meeting, session 4 of 17 / C, T |
| Big idea | Remote control and a stored program are different ways to give input. |
| Student objective | "I can predict and run two stored actions, then fix one instruction." |
| Why | A useful program runs in order and is checked against its purpose. |
| Catholic connection | Share tools fairly and choose a helpful purpose; teacher application of CCC 2407. Human dignity is not machine obedience. |
| Standards | Local CST-C2: fair partner turn/helpful purpose; CST-T1: run/stop and input/output; CST-T2: order two actions/debug. Official benchmarks: VERIFICATION REQUIRED. |
| Technology | **Required primary path:** Dash plus compatible tablet and **Blockly** to run stored instructions. Go driving alone does not meet programming objective. |
| Difficulty / prep / cleanup | Moderate; 20-30 minutes initial setup plus charging; 4 minutes cleanup included. |

## Before class
1. Confirm actual loan, compatibility/permissions and model charging instructions. Open Blockly, not just Go.
2. Test **drive forward 20 cm at low speed -> change light color** using installed block names; write tested settings on board. Show Run and Stop.
3. Mark a dry 1 m floor bay for each active kit, clear of exits; have a forward/light picture card and table token.
4. Assign teams of 2-3; rotate programmer, observer and checker after every run. No prior Year A/B coding assumed.

## Supplies
- **Per student:** half-sheet, crayon.
- **Per team:** one charged Dash/tablet kit, two cards, token.
- **Whole class:** floor tape, timer, board; reusable trays.
- **Teacher-only:** chargers, installed help, roster.

With three kits at 25, use three 4-minute waves (three teams/wave) at a teacher-supervised station; other teams predict with tokens. With one kit, not all children can receive adequate independent practice in 30 minutes: record missing device opportunities and repeat later. Do not count watching as operating/programming.

## Vocabulary / teacher background
Program = stored instructions; input = what we send; output = movement/light; sequence = order; debug = correct a mismatch.
Blockly is a stored block-based programming tool. Go joystick input steers in real time; it can illustrate input/output but cannot certify stored-code learning.
**Misconception:** pressing a drive button proves programming. Require a connected stored sequence.
**If asked about Carlo Acutis:** saint title/biography is optional; current official source is **VERIFICATION REQUIRED** before teaching details. A helpful technology choice can be assessed without a biography.

## Exact numbered sequence (30 minutes)
1. **0-4:** State objective, bay/stop rules, fair turns and helpful-purpose question. Optional original prayer asks for wise use.
2. **4-7:** Every child predicts two picture actions; partner moves a tabletop token and points to light picture.
3. **7-11:** Teacher contrasts manual Go steering with Blockly two-block stored run; shows how to stop. Do not say driving was programming.
4. **11-23:** Each child predicts/runs the tested sequence, swaps a color or movement amount and reruns. Observer says what changed; rotate after each run. Teacher records individual run/stop, sequence and one change.
5. **23-26:** Each child points/draws two actions and explains why the second run differed; state one fair turn/helpful purpose.
6. **26-30:** Cleanup.

## Questions / success
Can it run without steering? Which instruction changed output? Did your partner get an actual turn?
**Grade 1:** orally/visually order two actions, run/stop under supervision and point to one changed output. **Grade 2:** assemble two or three actions, predict, change one block and explain before/after. Both name a responsible use.
Score **not observed / prompted / independent** per child. Unplugged evidence never earns physical-robot operation credit.

## If things go wrong / indoor fallback
After two minutes checking charge/selected robot, use cards and token. Child orders two actions, partner follows, child fixes reversed order. Assess CST-T2 conceptual sequence/debug only; **no real robot programming or operation mastery**. Poor travel: shorten/lower speed on same dry surface. All work indoors.

## SAFETY / support / challenge
No racing, chasing, running on tables or touching a moving robot; stop outside bay. Teacher-only charging; keep cables out of routes. Consent before physical assistance.
Support: picture blocks, narrate each action, adult scribing and two-action starter. Challenge: Grade 2 add a short wait/light action; postpone maze/loops to a later measured opportunity.

## Cleanup / family / sources
Stop programs, power down, count kits/cards, clear tape and store labeled trays; teacher charges.
We distinguished steering from stored code, predicted a sequence and changed one instruction. Our Catholic connection was responsible sharing. Ask: "What ran without steering?" Optional: two spoken instructions for a paper token; no device/purchase or routine homework.

### Error interpretation and reteaching

- **Common error interpretation:** Compare the pupil's plan, action, and actual result. A mismatch means the prediction, sequence, condition, measurement, or explanation needs another check; it does not establish low ability, poor effort, or weak faith. Specifically guard against: **pressing a drive button proves programming. Require a connected stored sequence.**
- **Reteaching option within existing time:** Use the lesson's own fallback/support, not a new activity: **After two minutes checking charge/selected robot, use cards and token. Challenge: Grade 2 add a short wait/light action; postpone maze/loops to a later measured opportunity.** Re-model only **7-11: Teacher contrasts manual Go steering with Blockly two-block stored run; shows how to stop.
