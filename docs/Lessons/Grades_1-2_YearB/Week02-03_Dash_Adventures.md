# Weeks 2-3: Dash Robot Adventures

## Lesson at a glance
| Field | Teacher information |
|---|---|
| Grade / unit / title | Grades 1-2 / Coding / Dash Robot Adventures |
| Time / domains | Two 30-minute meetings / C, T, M |
| Big idea | A program is stored instructions; driving by joystick is a different kind of input. |
| Student objective | "I can run a short stored program and use a test to improve it." |
| Why | Responsible designers predict, test and share tools fairly. |
| Catholic connection | Respect every partner's contribution and agency; teacher application of human dignity and solidarity, CCC 2407. People are not robots obeying a programmer. |
| Standards | Local CST-C2: inclusive turn-taking; CST-T1: show input/output and stop; CST-T2: order/debug code; CST-M1: compare travel to target. Official benchmarks: VERIFICATION REQUIRED. |
| Technology | **Required primary path:** Dash and compatible tablet with Blockly, because children execute physical robot programs. Unplugged alternative assesses sequences, not robot operation. |
| Difficulty / prep / cleanup | Moderate; 20-30 minutes first setup plus manufacturer charging time; 4 minutes cleanup/meeting. |

## Before class
1. Confirm actual loan, model, school-approved app/permissions and charging guidance. Use [Blockly's official description](https://www.makewonder.com/apps/blockly/) and the installed block guide; do not assume generic Forward/Stop labels.
2. Test a short program on the actual floor: drive forward 20 cm at low speed; turn right 90 degrees; drive forward 20 cm. Write installed block labels/settings on board and show Run/Stop.
3. Mark 1 m dry floor bays and a paper target 20 cm ahead, clear of exits. Keep observers outside each bay.
4. Make three picture cards and a tabletop token. Assign teams of 2-3 with programmer, observer and safety-checker roles; swap after each run.

## Supplies / scaling
- **Per student:** half-sheet, crayon, teacher roster evidence box.
- **Per team:** one charged robot/tablet kit, three cards, token, 20 cm target strip.
- **Whole class:** tape, timer, soft paper target, whiteboard; no obstacle course needed.
- **Teacher-only:** chargers and installed app guide; cords stay stored during class.

| Students | Teams / kits for simultaneous practice | Papers |
|---|---:|---:|
| 10 | 4 | 10 |
| 15 | 5 | 15 |
| 20 | 7 | 20 |
| 25 | 9 | 25 |

At 25 use one supervised station with three 4-minute waves of three teams if only three kits exist; other teams rehearse with cards. If only one kit exists, teacher demonstration plus limited turns is **partial device assessment**: record children awaiting a turn, not universal mastery. Reduce moving robots to what the adult can safely supervise.

## Vocabulary / background
Input = our instructions; output = movement/light; sequence = instructions in order; program = stored instructions; debug = find/change a mismatch; distance = how far.
Blockly executes connected blocks. Manual Go control is not evidence of writing stored code. A robot may veer due to floor/charge; distinguish this from a wrong block.
**Misconception:** coding success is driving fastest. Accuracy and explanation matter.
**If asked "Does God program us?"** No. People make meaningful choices; this lesson's Catholic connection is responsibility and inclusion, not mechanical obedience.

## Meeting 1 (30 minutes)
1. **0-3:** State safe stop signal and sharing objective. Optional original prayer: "God, help us include every partner and learn honestly from our tests."
2. **3-7:** Predict a tabletop three-card sequence; each child moves token once.
3. **7-11:** Teacher shows stored Blockly program and contrasts with manual driving; demonstrate Run and Stop before student use.
4. **11-23:** Teams execute tested short programs. Each child predicts, runs/stops and compares ending to target; swap roles. Grade 1 may begin with forward plus light; Grade 2 adds the turn/second movement.
5. **23-26:** Individual oral/drawn exit: show input and output; order cards matching own run. Teacher records actual device participation.
6. **26-30:** Cleanup.

## Meeting 2 (30 minutes)
1. **0-4:** Recall the previous run; new entrants rehearse two cards rather than needing Year A.
2. **4-8:** Teacher deliberately makes the first movement too short; model prediction, observation and one distance change.
3. **8-20:** Each child changes one block/parameter, reruns and compares to target. Grade 2 describes nearer/farther before and after; no automatic maze completion or expertise claim.
4. **20-24:** Pairs show original versus changed sequence and explain output. Optional finite repeat of a light/wait sequence for ready Grade 2 children.
5. **24-26:** Individual evidence check and remaining-turn roster.
6. **26-30:** Cleanup.

## Questions / measurable success
What is stored before you press Run? How is this different from driving? Which instruction caused a change? How did your group include everyone?
- **Grade 1:** point to/orally order two actions, personally start/stop one stored run with supervision, show a change and one equitable turn choice.
- **Grade 2:** build/order three actions, predict the ending, change one instruction and explain observed improvement using nearer/farther or measured distance.
- Record **0 not observed / 1 prompted / 2 independent** for each child's sequence, device operation, debug and inclusion. No credit for a teammate's run.

## If things go wrong / no-device and indoor fallback
Connection: check correct robot and charge once; switch after two minutes, explicitly noting unassessed device skills. Token fallback uses the same prediction/change sequence; assess CST-T2 only, not Dash programming/operation mastery. Veering: stop and lower speed/shorten path on a flat surface. All work is indoors; no weather dependency.

## SAFETY / support / challenge
Low-speed dry floor bays only; stop if robot crosses boundary. Never chase, race, ride or hold a running robot. Teacher handles charging/cables. Safe accessible tabletop token alternative is available without stigmatizing a child.
Support: picture cards, narration, adult scribing, two actions and large buttons; nonreaders never copy typed directions. Challenge: Grade 2 explains two trials or a finite light loop, not sensors/autonomous navigation.

## Cleanup / family / sources
Stop, save only to school-controlled device as permitted, power down, count kits/cards, clear lesson tape and return to labeled trays; teacher charges.
**Family snippet:** We predicted and debugged stored robot instructions and shared turns respectfully. Ask: "What input changed the robot's output?" Optional: move a paper token with three spoken instructions; no device or purchase. No routine homework.
