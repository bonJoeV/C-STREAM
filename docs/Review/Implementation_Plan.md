# Prioritized implementation and change record

The repository review implements high-value changes rather than stopping at
recommendations. It does **not** certify every legacy activity as
classroom-ready, every official benchmark as covered, or the school's actual
inventory as sufficient.

## Priorities and release conditions

| Priority | Work | Owner to assign locally | Release evidence |
|---|---|---|---|
| P0 - Must fix | Unsafe or unspecified materials/procedures, inaccurate attribution, unverified required official-standard claims, unusable primary instructions | Principal/safety lead and teacher | Read the revised activity; identify hazards, stop rules and exact supplies. Remove or correct inaccurate claims. Hold unresolved P0 activities. |
| P1 - High priority | Complete remaining substitute directions, individual assessment, grade-specific prerequisites, low-tech/indoor alternatives and pacing | Curriculum lead and grade teachers | A second adult can teach from the document/kit; native period includes evidence and cleanup; younger/older expectations are explicit. |
| P2 - Improvement | Refine kits, replenishment counts, arts choices, data follow-up, accessibility and family communication | Teachers and materials coordinator | Pilot notes show a workable setup, each student's evidence and realistic resource use. |
| P3 - Enhancement | Additional robotics, software, digital creation, external visits and elaborate exhibitions | Program lead | A documented objective makes the additional cost/time worthwhile; privacy, availability and accessibility are approved. |

The audit's P0/P1 labels record **baseline priority**. A revised baseline P0
lesson can be released only after reviewing the revised procedure, not merely
because its CSV says `improved` or `rebuilt`.

## Substantive change record

- Recorded the 307-document baseline and all 251 lesson documents before
  restructuring; retained the 14 track directories and existing lesson URLs.
- Preserved 25/30/40/45-minute periods and alternative weekly/bi-weekly
  schedules with combined-grade Year A/B entry points.
- Replaced misleading filename totals and overlapping time quotas with
  document/meeting distinctions. Corrected the generic planner's extension

  completeness and structural consistency, not academic or safety approval.

## Recommended implementation cycle

| Window | Action | Completion evidence |
|---|---|---|
| Before the next class | Select a revised reference lesson; verify supplies, period length, accommodations and safety. Avoid unresolved P0 activities. | Teacher initials an actual lesson/kit checklist. |
| First two teaching meetings | Pilot one younger-grade and one older-grade reference lesson using the no-device path where available. | Actual prep/cleanup time, student explanations, supply use and teacher notes. |
| First month | Review individual evidence against local grade expectations; fix the next scheduled P1 lessons before teaching them. | Lesson revisions and a small dated evidence portfolio. |
| Before claiming official alignment | Match applicable official benchmarks to exact lesson tasks and assessment; seek local curriculum/diocesan guidance as appropriate. | Source URL, identifier/version, reviewer/date and evidence link. |
| Each term | Rebalance domain exposure, review returning students' progression, replenish kits and simplify high-prep activities. | Updated audits, inventory and scope/calendar. |
| Annually | Recheck implementation years, prices, equipment, school calendar and family accessibility. | Dated source register, working-kit check and revised maps. |

## Final completion gate

Do not label the entire program "substitute-proof" until every **scheduled**
core lesson has passed the document/kit walkthrough and classroom pilot.
The written package queues are closed; this gate refers to real local release
evidence, not another unimplemented lesson-outline backlog.
The [seven simulations](Validation.md) are necessary desk checks; actual
student learning and classroom timings need observed evidence.
